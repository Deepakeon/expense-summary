Lesson 0010 • Telemetry & Monitoring

Agentic Observability: Turning the Black Box into a Dashboard

How to monitor every tool call, MCP execution, and token count using live stream events and Arize Phoenix.

The Problem: The Autonomous Black Box

When our self-hosted runner executes agy --print "...", the terminal only shows final markdown or scrolling text. If the agent runs five shell commands and hangs on the sixth, standard logs leave crucial questions unanswered:

  • Which tool slowed down? Did npm test take 40 seconds, or did an MCP call stall?
  • What parameters were passed? Exactly what command line flags or file paths were executed?
  • What was the output? Did a tool fail silently with an exit code error?
  • Where went the tokens? How many tokens were spent on reasoning versus prompt context?

Observability replaces guesswork with a flight recorder: an interactive dashboard displaying an end-to-end timeline of every action your agent takes.

The Architecture: 3 Moving Parts

We connect the Antigravity runner to a visual dashboard via three lightweight components:

  1. The Emitter (agy --output-format stream-json): Instead of plain text, the CLI emits structured JSON events line-by-line in real time as actions occur.
  2. The Forwarder (telemetry_forwarder.py): A lightweight Python script that reads the stream and translates tool start/finish events into OpenTelemetry spans.
  3. The Dashboard (Arize Phoenix): An open-source, self-hosted container running on http://localhost:6006 that graphs nested tool spans, latencies, and token burn. 
agy --output-format stream-json ... \
  | python3 scripts/observability/telemetry_forwarder.py \
  | tee agent-output.log → sends OTLP spans to http://localhost:6006/v1/traces

How a Tool Call Becomes a Visual Span

In stream-json, every tool execution produces two distinct events:

1. Tool Starts (State: ACTIVE)

The forwarder opens a new OpenTelemetry span named tool_run_command and records the input arguments:

{"event":"step_update","step_update":{"step_index":2,"state":"ACTIVE","step_type":"tool","tool_name":"run_command","tool_info":{"parameters":{"CommandLine":"npm test"}}}}
2. Tool Finishes (State: DONE)

The forwarder closes the span, attaching exact duration and tool output:

{"event":"step_update","step_update":{"step_index":2,"state":"DONE","step_type":"tool","tool_name":"run_command","duration_seconds":3.42,"tool_info":{"output":"PASS __tests__/sync.test.ts"}}}

Phoenix visualizes these spans as a nested flame graph: the root agent task sits at the top, branching downward into individual LLM thinking turns and tool calls.

Quick Win: Start Phoenix Locally

You can spin up Phoenix right now on your machine with one Docker command:

docker run -d --name phoenix -p 6006:6006 --restart unless-stopped arize/phoenix:latest

Once running, open http://localhost:6006 in your browser to view your live traces dashboard.
