Step 2: The Matt Pocock Debugging Framework

The workflow loads Matt Pocock's skills into the local agent. When an issue arrives, the agent executes this mandatory 5-phase loop:

Phase 1 — Build a Tight Red Feedback Loop

Before writing fixes or guessing causes, construct one single deterministic test command (e.g. npm test -- -t "repro test") that predictably fails on the reported defect. If you cannot make it red, stop.

Phase 2 — Reproduce + Minimise

Shrink the reproduction to the absolute smallest scenario. Cut inputs, config, and unrelated files one by one until every remaining element is load-bearing.

Phase 3 — 3–5 Ranked Falsifiable Hypotheses

Generate multiple competing theories before testing any: "If X is the cause, then changing Y will make the symptom disappear." Never anchor on the first idea.

Phase 4 — Targeted Instrumentation

Insert temporary tagged logs prefixed with [DEBUG-...] to verify internal state. Never commit untagged console logs.

Phase 5 — TDD Fix & Clean Verification

Write the minimal code change to turn the reproduction green. Clean up all debug harnesses, run full tests, and open the pull request.
