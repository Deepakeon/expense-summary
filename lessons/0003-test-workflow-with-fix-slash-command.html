Testing /fix on Issues with Your Local Runner

Push the compiled workflow to GitHub, activate your runner listener, and trigger the agent via issue comment.

How the /fix Trigger Works

In .github/workflows/bug-resolver.md, the workflow is configured to listen for issue events:

on:
  slash_command:
    name: fix
    events: [issues, issue_comment]

When you comment /fix on any GitHub issue:

  1. GitHub dispatches an issue_comment webhook.
  2. GitHub Actions reads the workflow lockfile from the repository default branch (main).
  3. The agent job evaluates its target runner: runs-on: self-hosted.
  4. Your local machine picks up the job from the outbound poll queue.
  5. The agent executes Matt Pocock's diagnosing-bugs loop locally, runs tests, fixes the defect, and creates a pull request.

Step-by-Step Test Procedure

Step 1 — Commit & Push Workflow to Default Branch

GitHub Actions only triggers slash commands from workflows present on main:

git add .github/workflows/bug-resolver.md .github/workflows/bug-resolver.lock.yml
git commit -m "feat(ci): route bug-resolver agent to self-hosted runner"
git push origin main
Step 2 — Start Your Local Runner Listener

In a separate terminal window, launch the runner:

cd ~/actions-runner
./run.sh

Verify the output shows:

√ Connected to GitHub
Current runner version: '2.337.0'
Listening for Jobs
Step 3 — Create a Test Issue & Trigger /fix

Create a test issue via CLI or GitHub web UI:

gh issue create \
  --title "test: verify self-hosted runner bug-resolver" \
  --body "/fix verify runner execution with diagnosing-bugs skill"

Or open an existing issue in Deepakeon/expense-summary and post a comment: /fix.

Step 4 — Watch the Execution Live

As soon as the comment is posted:

  • Your ./run.sh terminal will immediately log: Running job: agent.
  • Track the GitHub workflow run in real time:
gh run watch
