Automated Pull Request Creation

Your runner successfully diagnosed and pushed the fix branch; now automate the GitHub PR creation step.

What Actually Happened in Your Run

Your runner job completed with Succeeded because Antigravity (agy) did its job:

  • It read Issue #1 and applied Matt Pocock's diagnosing-bugs loop.
  • It implemented the fix and verified the test suite passed.
  • It created a new Git branch: fix/issue-1.
  • It committed the changes (2af16e1) and pushed them to GitHub (origin/fix/issue-1).
Why No PR Was Visible The prompt instructed agy to "commit changes, and push". It did not invoke gh pr create. The branch was pushed to GitHub, but the PR had not been opened yet.

Automating PR Creation in Future Runs

In antigravity-fix.yml, we added an automated step that runs immediately after agy finishes:

      - name: Open Pull Request
        if: success()
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          ISSUE_NUMBER: ${{ github.event.issue.number }}
          ISSUE_TITLE: ${{ github.event.issue.title }}
        run: |
          BRANCH="fix/issue-$ISSUE_NUMBER"
          if git ls-remote --exit-code --heads origin "$BRANCH"; then
            gh pr create \
              --base main \
              --head "$BRANCH" \
              --title "fix: resolve issue #$ISSUE_NUMBER ($ISSUE_TITLE)" \
              --body "Fixes #$ISSUE_NUMBER. Diagnosed and resolved by local Antigravity runner using Matt Pocock's diagnosing-bugs discipline." || echo "PR already open"
          fi

Now, whenever you comment /fix, the runner will resolve the bug, push the branch, and automatically open the PR.
