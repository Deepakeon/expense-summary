Lesson 0004 • Architecture & Cost Control

Running Antigravity Directly (Zero API Cost)

Bypassing gh-aw's Gemini CLI to execute your authenticated local Antigravity (agy) agent without token costs or rate limits.

The Critical Difference: Gemini CLI vs. Antigravity CLI

If you push bug-resolver.md as compiled by gh-aw, Antigravity will NOT run. Instead:

  • gh-aw has engine: { id: gemini } hardcoded.
  • It installs @google/gemini-cli@0.43.0 via npm and runs gemini.
  • It calls generativelanguage.googleapis.com using your GEMINI_API_KEY secret.
  • Result: It consumes cloud API tokens and is vulnerable to Google Cloud rate limits.
The Solution Because your runner is self-hosted on your machine, it has direct access to your authenticated agy CLI at ~/.local/bin/agy. By calling agy directly in a native GitHub Action step, you bypass the cloud API completely and use your unlimited Antigravity session.

Native Antigravity Workflow Template

Create a dedicated native workflow: .github/workflows/antigravity-fix.yml:

name: Antigravity Fixer

on:
  issue_comment:
    types: [created]

jobs:
  antigravity-fix:
    if: startsWith(github.event.comment.body, '/fix')
    runs-on: self-hosted
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Execute Antigravity Agent
        env:
          ISSUE_NUMBER: ${{ github.event.issue.number }}
          ISSUE_TITLE: ${{ github.event.issue.title }}
          ISSUE_BODY: ${{ github.event.issue.body }}
          COMMENT_BODY: ${{ github.event.comment.body }}
        run: |
          # Add local bin to PATH where agy lives
          export PATH="$HOME/.local/bin:$PATH"

          # Execute Antigravity CLI with existing local authentication
          agy --print "You are resolving issue #$ISSUE_NUMBER: $ISSUE_TITLE.
          Details: $ISSUE_BODY
          Instructions: $COMMENT_BODY

          Strictly apply Matt Pocock's diagnosing-bugs and TDD disciplines:
          1. Build a tight reproduction test in __tests__/ that fails on this defect.
          2. Form falsifiable hypotheses and verify minimal fix.
          3. Run 'npm test' to verify green.
          4. Create a Git branch 'fix/issue-$ISSUE_NUMBER' and commit the solution."
