Lesson 0001 • Local Runner Setup

Provisioning & Registering Your Local Runner

Connect your Linux workstation to GitHub Actions so workflows execute locally with authenticated Antigravity.

The Mission Alignment

By connecting your workstation as a self-hosted runner for Deepakeon/expensse-summary, your GitHub workflows run directly on your hardware. This unlocks immediate benefits:

  • Credential reuse: The runner runs as your local Linux user, with instant access to your authenticated agy CLI and tokens.
  • Bypass cloud API limits: Avoid GitHub-hosted Actions minute caps and cloud runner quotas.
  • Native tooling: Local compilers, emulators, and local caches are immediately available to the workflow.

How the Runner Communicates

A common misconception is that running workflows on a local machine requires opening ports in your home router or configuring port forwarding. In reality, the GitHub runner agent uses outbound long-polling over HTTPS (port 443).

Key Architectural Takeaway Your runner initiates the connection to GitHub's message queue. GitHub never connects back directly to your local IP address. You do not need any firewall exceptions, dynamic DNS, or public IP configurations.

Hands-On: Provision Your Runner

Step 1 — Prepare Directory & Download Archive

Run these commands on your workstation to create an isolated directory outside the project repo and download runner v2.337.0:

mkdir -p ~/actions-runner && cd ~/actions-runner
curl -o actions-runner-linux-x64-2.337.0.tar.gz -L https://github.com/actions/runner/releases/download/v2.337.0/actions-runner-linux-x64-2.337.0.tar.gz
echo "70920811a4f8ad4328818682bca5c6469c1c942fab52448868071d0063816613  actions-runner-linux-x64-2.337.0.tar.gz" | shasum -a 256 -c
tar xzf ./actions-runner-linux-x64-2.337.0.tar.gz
Step 2 — Generate Registration Token & Configure

Using your authenticated gh CLI, fetch a temporary registration token and register the runner:

# Generate token
TOKEN=$(gh api --method POST repos/Deepakeon/expensse-summary/actions/runners/registration-token --jq .token)

# Register runner with default settings
./config.sh --url https://github.com/Deepakeon/expensse-summary --token $TOKEN

Press Enter to accept default runner name and work folder (_work).

Step 3 — Start Interactive Listener

Start the runner process to confirm successful connection:

./run.sh

You should see Listening for Jobs in your terminal, and the runner will display as Idle / Online in your repo's Settings → Actions → Runners.
