Structured PR Body: Issue Link, Root Cause & Fix

Ensuring every pull request explains why the issue occurred, how it was resolved, and automatically links the ticket.

PR Format Requirements

A professional pull request created by an agentic runner must answer three questions:

  1. Issue Link: Starts with Closes #<id> to link the PR and automatically close the issue on merge.
  2. Why Was It Happening (Root Cause): Matt Pocock diagnosis explaining why the defect occurred in production.
  3. What Was the Fix (Solution & Verification): The exact code changes made and the regression tests in __tests__/ verifying it.

Live Example: PR #4

Review the updated pull request demonstrating this structure:

→ PR #4 on GitHub

Closes #1

## Why Was It Happening (Root Cause)
1. SMS Sender Matching Failure: Indian telecom operators prepend circle prefixes (VM-, VK-, AD-) and append service suffixes (-S, -T) to sender headers. matchesSender did not normalize bidirectionally.
2. Native Module Discovery: SmsReaderModule.kt lacked @ReactModule for New Architecture discovery.

## What Was the Fix (Solution & Verification)
1. Added normalizeSender in TypeScript and Kotlin to strip prefixes/suffixes.
2. Added @ReactModule annotation and dynamic native module resolution.
3. Added unit tests in __tests__/syncService.test.ts; all pass green with npm test.

Automated Workflow Generation

In antigravity-fix.yml, the agent is instructed to write pr-summary.md. The workflow then injects this into gh pr create:

PR_BODY=$(printf "Closes #%s\n\n%s" "$ISSUE_NUMBER" "$(cat pr-summary.md)")
gh pr create --body "$PR_BODY" ...
