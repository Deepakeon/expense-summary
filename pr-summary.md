## Why Was It Happening (Root Cause)
1. **SMS Sender Matching Failure**: Indian telecom operators prepend circle routing prefixes (`VM-`, `VK-`, `AD-`, `BZ-`) and append service suffixes (`-S`, `-T`) to sender headers. The sender matching logic (`matchesSender`) only checked one-way suffix matches assuming sender rules never carried prefixes. When users configured rules with prefixes (e.g., `VM-HDFCBK`) or received messages with varying circle prefixes or suffixes, matching failed bidirectionally, causing the messages to be skipped.
2. **Native Module Discovery**: `SmsReaderModule.kt` lacked the `@ReactModule(name = SmsReaderModule.NAME)` annotation required by React Native's New Architecture for runtime module discovery. In addition, static destructuring of `NativeModules.SmsReaderModule` at module import time could fail if native module initialization was deferred.

## What Was the Fix (Solution & Verification)
1. **Bidirectional Sender Normalization**: Added `normalizeSender` in both [src/sync/syncService.ts](file:///home/deepak/actions-runner/_work/expense-summary/expense-summary/src/sync/syncService.ts) and [SmsReaderModule.kt](file:///home/deepak/actions-runner/_work/expense-summary/expense-summary/android/app/src/main/java/com/expensesummary/sms/SmsReaderModule.kt) to strip 2-character circle prefixes and trailing service suffixes. Updated `matchesSender` to verify matches against normalized senders bidirectionally.
2. **New Architecture Module Discovery & Dynamic Lookup**: Annotated `SmsReaderModule` with `@ReactModule(name = SmsReaderModule.NAME)` and updated [src/sms/smsReader.ts](file:///home/deepak/actions-runner/_work/expense-summary/expense-summary/src/sms/smsReader.ts) to resolve `NativeModules.SmsReaderModule` dynamically via getter.
3. **Automated Unit & Regression Tests**: Added regression tests in [__tests__/sync/syncService.test.ts](file:///home/deepak/actions-runner/_work/expense-summary/expense-summary/__tests__/sync/syncService.test.ts) covering sender matching with telecom prefixes/suffixes and multi-message batch extraction across `VM-HDFCBK`, `VK-HDFCBK`, `HDFCBK`, and `VM-HDFCBK-S`. All 9 test suites (41 tests) pass.
